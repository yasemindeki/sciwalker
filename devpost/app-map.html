Key files

FileWhat it doesKind
src/index.tsx Entry point. Validates args and file, runs extraction, mounts Ink app. code
src/agent/extractor.ts Strands agent loop. Defines the submit_concepts tool with a Zod input schema. Calls Bedrock once per run and collects candidates and failures. AI
src/agent/segment-resolver.ts Parses the transcript into structured lines. Resolves start_time/end_time from the verbatim quote text — deterministic, not LLM-provided. code
src/schema/knowledge-item.ts Zod schemas for CandidateKnowledgeItem, ApprovedKnowledgeItem, and the FailedKnowledgeItem interface. The contract between agent and TUI. code
src/tui/App.tsx Root Ink component. Manages four sequential modes: startup → review → failure → close. Accumulates approved cards across the review loop. TUI
src/tui/StartupBlock.tsx Shows candidate count (and failure count if any). Waits for Enter to begin review. TUI
src/tui/CardReview.tsx Displays one card at a time with all fields. Accepts [a]pprove / [r]eject via useInput. Visual separator between AI-generated and source fields. TUI
src/tui/FailureBlock.tsx Shows each Zod validation failure: ID, error message, raw model output. Press [n] to advance. Nothing is silently lost. TUI
src/tui/CloseBlock.tsx Calls writer.ts, shows final summary line, exits. Deletes output file if all cards were rejected. TUI
src/output/writer.ts Auto-creates output/ dir, validates each card against ApprovedKnowledgeItemSchema, writes pretty-printed JSON array. code

The key design decision

LLM for semantics, code for structure.
The Strands agent decides what to extract and how to classify it. segment-resolver.ts decides where the quote appears — by searching the transcript text directly, not by trusting the model's timestamps. Zod validates the boundary between the two. This pattern applies anywhere LLM output needs to be verified, grounded, or persisted.
